## Bug 1 — Teks PDF terlihat bertumpuk saat diseleksi

### Akar masalah (bukan dugaan)

1. **Warna**: `.text-layer` memakai `color: transparent`, tetapi gaya bawaan peramban untuk
   `::selection` menimpanya dengan `color: HighlightText` (opak). Saat pengguna menyorot,
   glyph lapisan teks **terlihat kembali di atas bitmap** → tulisan tampak dua kali.
2. **Geometri**: setiap run teks diletakkan dengan `left/top/width/height` dari kotak PDF,
   tetapi glyph-nya dirender dengan **font UI**, bukan font PDF. Kotak DOM (line box) sehingga
   tidak sama dengan kotak PDF → sorotan menggeser relatif terhadap tulisan yang tampil
   (terlihat sebagai "bergeser"), dan teks yang disorot tidak mengikuti teks aslinya.
3. **Span basi**: `PageSurface` selalu meneruskan `spans={null}`, sehingga lapisan teks
   mengambil ulang data tiap kali halaman dirender ulang, dan cache tidak pernah dipakai.

### Perbaikan

| File | Perubahan |
|---|---|
| `src/styles.css` | Aturan `::selection` **terarah pada `.text-layer`** (bukan seluruh aplikasi): `color: transparent` + `background-color: rgba(56,130,246,0.28)` (transparan → tulisan asli di bawahnya tetap terbaca). `color`/`-webkit-text-fill-color: transparent` pada span. Overlay debug hanya lewat `.text-layer[data-debug="1"]` |
| `src/viewer/geometry.ts` (baru) | `spanTransform()` menghitung **skala horizontal** (lebar run DOM → lebar kotak PDF) dan **offset vertikal** relatif (pusat ink box pada kotak target). Keduanya relatif, bukan offset piksel tetap → tetap benar di semua zoom/DPI. `measureRun()` mengukur font UI lewat canvas (ascent/descent/width) |
| `src/components/TextLayer.tsx` | Mengukur tiap run lalu menerapkan `transform: translateY() scaleX()`; menyimpan `data-target-width/height` untuk diagnostik; `font-size` = tinggi kotak PDF |
| `src/components/PageSurface.tsx` | Meneruskan cache span milik induk (`spans`/`onSpans`) |
| `src/components/DocumentView.tsx` | Cache span per `docId:revision:page` (dibatasi 400 entri, dibersihkan saat dokumen/revisi berubah) → tidak ada span basi yang tertinggal |
| `src/debug.ts` (baru) | Diagnostik geometri lokal (hanya build dev `VITE_UNIONPDF_DEBUG=1`): warna layer, warna `::selection`, jumlah run, deviasi kotak. Tidak ada di build pengguna |

## Bug 2 — Auto-scroll hanya ke bawah

### Akar masalah

Arah **sudah** diimplementasikan (`dir = -1` untuk naik → `scrollByPixels(-px)`), tetapi
kontrolnya **hanya satu tombol toggle** dan ikon panah **tidak pernah berbalik**: kelas CSS
`.flip` ter-scope ke `.searchbar .icon-btn .flip`, sedangkan panel auto-scroll memakai
`className="flip"` → aturan tidak berlaku. Akibatnya tombol terlihat sama saja dan pengguna
tidak pernah menemukan arah "naik".

### Perbaikan

- `src/components/AutoScrollControl.tsx`: **dua tombol arah berlabel eksplisit** `[Naik] [Turun]`
  (`aria-pressed` mencerminkan arah aktif, `aria-label`/tooltip jelas), tombol Mulai/Jeda, slider
  kecepatan + nilai kecepatan, penanda "jeda" dan "ujung dokumen".
- `src/components/icons.tsx`: `IconChevronUp` baru; `.flip` diganti `.icon-flip` (scope global).
- `src/App.tsx`: `atEdge` dilacak → tombol berhenti di ujung dokumen, status "ujung dokumen".
